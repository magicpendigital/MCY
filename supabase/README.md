## Security boundaries

- Client access uses the publishable key only; never place a service-role/secret key in the app.
- Learner-owned check-in, dialogue, plan, run and reflection tables use owner RLS policies.
- Draft content, rights, review events, availability and AI grants are deny-by-default and should be changed by a server-side API/admin boundary.
- The `private` schema is not granted to `anon` or `authenticated` and is not a client Data API surface. Live ACL checks on staging also show that `service_role` currently has no `USAGE` or table privileges on `private.role_assignments` or `private.teacher_assignments`; do not assume its key alone grants access. Before a backend uses these tables, design the smallest server-only grant or narrowly scoped SECURITY DEFINER API and test the actor boundary. Never expose private records through client grants.
- `private.push_endpoints.token_ciphertext` must be encrypted with a KMS-managed key; `token_hash` is used for deduplication. Never log the plaintext push token.
- `private.share_grants` is the source of truth for time-bounded, field-scoped teacher/support access. The server must select only approved fields and write an audit event for every access.
- `private.job_runs` is the idempotency ledger for exports, media processing, notifications and AI work. Use `(job_type, idempotency_key)` for retries instead of duplicating side effects.
- Private media buckets and Storage policies are intentionally not created by the learner database migrations. The newly authorized teacher trial needs a separate reviewable migration/API gate before any bucket is created. Keep lesson uploads private and staged; teacher trial uploads cannot be learner-visible or published.

## Deliberately staged hardening

The first attempt to combine new tables with changes to existing public RLS policies, content immutability triggers and teacher activation rules was rejected by the automatic safety review because of its blast radius. The later `harden_teacher_profile_acl` migration is deliberately limited to client privileges and the three self-write policies on `public.teachers`; it does not create a teacher API, activate profiles, issue invitations or provide media access. Keep those features behind separate contract-tested server/API and policy gates.

On 2026-09-30, live staging review found `anon` and `authenticated` had broad SQL privileges (including `TRUNCATE`) on `public.sessions`, `public.session_versions`, `public.session_segments` and `public.editorial_versions`. Migrations `20260930035823_lock_teacher_draft_direct_writes.sql` and `20260930040857_lock_editorial_draft_direct_writes.sql` remove all direct client privileges except SELECT. Migration `20260930041541_disable_direct_draft_write_policies.sql` also removes the legacy client INSERT/UPDATE policies that checked owner/author IDs but not active server-granted roles. Existing RLS policies continue to constrain reads. No teacher profiles, session draft rows, or editorial items/versions existed at the time of the checks. Do not re-grant draft writes to browser/mobile roles; future teacher/editorial authoring must use a reviewed server boundary with active-role, ownership and audit checks. These migrations were applied through the authorized Supabase connector because the local Supabase CLI was unavailable; exact remote versions are recorded in filenames.

A broader attempt to revoke all client table, sequence and function privileges across the whole `public` schema and change all corresponding default privileges was rejected by the automatic safety review as too high-blast-radius without a specific compatibility/test plan. Do not retry that schema-wide operation indirectly. Any future proposal requires owner approval plus an explicit allowlist of required RPC/table access and learner/auth regression tests. Current per-object hardening does not change schema-wide defaults; continue treating new public tables/functions as gated until grants are reviewed.

The latest live ACL/source reconciliation and proposed per-role allowlist are recorded in [`analyse/MCY_STAGING_ACL_ALLOWLIST_2026-09-30.md`](../analyse/MCY_STAGING_ACL_ALLOWLIST_2026-09-30.md). It is evidence and a proposal, not authorization to apply the broader ACL/default-privilege changes.
