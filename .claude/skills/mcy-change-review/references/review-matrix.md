# MCY review matrix

Choose the highest applicable tier, then add tests for the changed behavior. Never downgrade a change because a needed suite does not yet exist.

| Tier | Typical trigger | Required evidence |
|---|---|---|
| R0 | Documentation or copy with no behavior change | Diff, source-of-truth and link/wording review. |
| R1 | UI, localization or learner flow within existing contracts | `npm run check:runtime`, `npm run build`, `npm run check:bundle-secrets`, `npm run test:sites`; select meaningful affected Playwright cases (including protected runtime cases when impacted), flow/manual QA for changed and adjacent branches, device presets, viewport, keyboard and accessibility. Inspect current scripts/config before selecting a bounded regression set; a full unrelated UI suite is not required by default. These local tests cover fixtures only. |
| R2 | Persistent state, Supabase schema/RPC/RLS, API, uploads, playback or provider switch | R1 where app affected; contract/integration tests, negative actor/object access matrix, error/retry/quota cases, migration from clean and previous schema, staging smoke with fictional data. Prove private media remains private. |
| R3 | Auth/consent, health guidance, teacher/admin rights, real AI, protected runtime/lock, CI/skill gate, secret handling, release or destructive migration | R2 as relevant; focused threat review, forbidden-action tests, reviewer with appropriate expertise, staged rollout and a tested stop/restore path. Do not expose without these gates. |

Current scripts are defined by `package.json`; inspect test source and Playwright config/testMatch rather than relying on dated suite counts. Map checks to the intake impact and preserved behavior in the [task lifecycle](../../../../docs/quality/TASK_LIFECYCLE.md). `npm run test:runtime` currently invokes Playwright; use explicit affected file/case selection where appropriate and report that scope. A fixture pass does not establish authenticated live writes, role/RLS/media isolation, physical devices or complete English support. The GitHub workflow is not proven active until it runs on a PR and the repository rule requires it. A suite only counts as PASS after its process exits successfully in the relevant environment; if all test cases print `ok` but the runner hangs or must be interrupted, record the cases and runner status separately.

The bundle check detects known Supabase secret-key/JWT patterns in built client text files; it is not a general secret scanner. The CI baseline runs `npm audit --omit=dev --audit-level=high`; review reported moderate advisories and any new package/lockfile change as well. Neither result substitutes for permission tests or a focused security review.

For auth/data, cover anon, learner A, learner B, teacher, reviewer and owner as applicable; attempt direct table writes, cross-user IDs, expired/revoked grants and stale consent. For media, check file type by content, size, ownership, scan/quarantine, signed URL expiry, cache and no draft publication. For native/web changes, test simulator iPhone/Pixel, real mobile browser and physical devices available; report missing device evidence. For AI/content, test source/version, no-match, missing/worse feedback, user correction, prompt injection, withdrawal and human review of instruction quality.

For body-region/RPC changes, review the locale-neutral region-code contract and JSON key shape from the app through the public consent-checked wrapper into its private SECURITY DEFINER writer. Verify the wrapper's live owner, empty pinned `search_path`, actor and consent checks, helper EXECUTE denial, unchanged direct table grants, idempotency and row ownership. Keep existing profile preferences and observations unchanged during expansion. Test anonymous denial, authenticated valid save and readback, stale/revoked consent, duplicate/overlapping side values and cross-user IDs using disposable fictional staging actors; if an authenticated fixture is unavailable, mark that part CHƯA CHẠY and do not call catalog checks a complete actor test.

Before any teacher endpoint or bucket accepts a real upload, prove on the actual staging ACL/RLS that an ordinary authenticated account cannot insert or update `public.teachers` with `active=true` or otherwise grant its own role. Fix and retest that path first. Keep new teacher endpoints disabled or limited to internal allowlisted test users until the gate passes; a staging endpoint reachable by external invitees is exposed. A service-role API must check an active server-owned role, the owner of the draft and object key, and permitted state **when issuing an upload URL, finalizing an upload, and issuing a download/playback URL**. Test role revocation between those steps and another teacher's object key. Deny new tokens immediately after revocation; a bearer URL issued earlier remains usable until its TTL unless explicitly invalidated, so test that exposure window. A pending object stays private/quarantined; do not make it reviewer-visible or learner-visible before content type/size, security scan and rights evidence pass. External invitations and real uploads still require the roster, privacy/rights statement and reviewer specified in `AGENTS.md`.

Protected runtime hashes may be refreshed **only** for an explicitly authorized runtime change after simulator/native behavior is verified. A PR that changes the checker, lock, migrations, auth, release policy or these skills needs review of the control itself. The CI job in the same PR and CODEOWNERS text alone are not independent enforcement; a trusted branch ruleset and restricted deploy/database credentials are separate operational gates.

When this skill's gates change, validate syntax and forward-test at least a low-risk copy edit, a real UI behavior change and a high-risk permission/media scenario. Record any gap found and correct it before relying on the revised rule.
